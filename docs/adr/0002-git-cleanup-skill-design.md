# 2. Git クリーンアップスキル (git-cleanup) のアーキテクチャと安全設計

- **ステータス**: Accepted
- **日付**: 2026-08-19
- **対象**: `.agents/skills/git-cleanup/`

---

## 1. コンテキスト (Context)

日々の開発作業に伴い、マージ済みのローカルブランチ、リモートで削除されたブランチの残骸（`[gone]`）、紐づく Git worktree、およびリモートブランチ（`origin`）が蓄積し、リポジトリの参照が煩雑になる課題があった。

これらの不要リソースを AI エージェント経由（およびターミナル手動実行）で安全かつ高速に一括整理・削除するスキルを導入することとなった。

---

## 2. 決定事項 (Decision)

1. **配置スコープ**:
   - リポジトリ固有のワークスペーススキルとして `.agents/skills/git-cleanup/` に配置する。
2. **実装形態（ハイブリッド型）**:
   - プロンプトのみで AI に Git コマンドを都度打たせるのではなく、検証済みのヘルパースクリプト（`scripts/cleanup.sh`）を同梱する。
   - スクリプトによる一括解析（`--dry-run`）とエージェントによる対話型確認（ユーザーへの一覧提示と承認）を組み合わせ、AI の解釈ブレや誤削除を防ぎつつトークンと実行時間を節約する。
3. **安全・保護ポリシー**:
   - **保護ブランチ**: `main`, `master`, `develop`, `development`, `release/*`, `staging`, `production` および現在チェックアウト中のブランチは自動保護し、絶対に削除しない。
   - **Worktree 安全ガード**: 未コミット変更（staged/unstaged/untracked）が存在する Worktree は削除をブロックし、警告を出してスキップする（紐づくブランチも保持）。
   - **対話確認の必須化**: 削除前に Dry-Run で削除候補とスキップ対象を明示し、ユーザー承認を得てから削除を実行する。
4. **対象範囲のデフォルト設定**:
   - デフォルトでローカルブランチ、クリーンな Worktree、リモートブランチ（`origin` 上のマージ済みブランチ）をすべて対象とする。
   - リモートブランチを触らずローカルのみに限定したい場合は `--local-only` オプションを提供する。

---

## 3. 結果・影響 (Consequences)

### メリット
- **高い安全性と再現性**: 複雑な Git 状態（Worktree の dirty チェック、gone 判定、保護ブランチ除外）がスクリプトで機械的にテスト・保証される。
- **効率性**: 1回のスキャンで全リソースの状態を把握でき、AI のトークン消費と実行待ち時間を大幅に削減。
- **柔軟性**: エージェント経由（`/git-cleanup`）だけでなく、開発者がターミナルから直接スクリプトを実行することも可能。

### 制約・留意点
- リモートブランチの削除や `git fetch --prune` を行うため、ネットワーク接続および適切なリモート操作権限が必要。
